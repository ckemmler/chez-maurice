# Maurice — the digest

A condensed reference to the system documentation ([[maurice-docs]] and the notes under it), written 19 September 2026. Each section states what a part *is*, the names a person needs (routes, files, scripts, variables), what ships versus what only exists, and the known gaps. The history of how each thing came to be is in the full notes; this keeps the facts. The `covers` map in the frontmatter names the note dates this digest reflects: a note updated since is read in full beside it.

Two distinctions run through everything. **Ships vs. exists**: the public product is chat + the garden + corpus search; the wider capabilities (Calibre, tasks, coaching, health, tracks, mail…) live in the private `maurice-tools` overlay, are in daily use at home, and are *experimental*. **Vision vs. built**: the founding vision ([[maurice]]) describes a household AI with a tamed, visible memory; these docs describe what is built and flag the gaps.

## Concept — the why

Maurice is a self-hosted **household AI assistant** with a scoped, visible memory: the *garden*, a folder of Markdown notes per member, git-backed, that grows only by deliberate human action — nothing enters it without an explicit request. "Apprivoisé" (tamed) is the stance: the member chooses exactly what Maurice knows for a conversation. Hats are chosen personas. Sovereignty means the data stays where the household put it: no cloud account, no analytics, no email; and since September 2026 a single European supplier, Scaleway, can provide both the machine and the model, so nothing need leave the EU. "Small on purpose": the right-sized win is a few hundred households, used by people who are not its author.

Vision items **not built**: the "temporal mirror" (automatic daily/weekly reviews), Maurice noticing patterns and proposing notes (not intended either), emergent hats derived from the active note subtree, consent-driven persona creation.

## Architecture — the five parts

- **Maurice app** (`app/Maurice`, SwiftUI, one target for iPhone/iPad/Mac): the conversation client. Holds no authoritative state; pairs to a server, authenticates a member, talks HTTPS + WebSocket. Dictation, cost meter, hats, composer.
- **Carnet** (separate repo `carnet/`, iOS/iPadOS): the pocket companion for capturing and reading — log signals, read books and articles, browse the garden, save what you read via a share sheet.
- **Server** (`server/`, one Bun process on Hono): `server/src` is the chat engine (auth, users, conversations, personas, files, gardens, composer, models, reports, the streaming agentic loop); `server/data-api` is the personal-data layer at `/api/v1/*` (health, tasks, signals, tracks, coaching, Calibre, bank, layouts, places, uploads, and the garden's media: articles, entries, résonances, flashcards).
- **Tools** (`tools/`): Python MCP servers behind one `mcp_gateway`, reached by the server over loopback. Public: `garden`, `corpus`, `shared`, `mcp_gateway`. Private overlay (`maurice-tools` repo, symlinked): tracks, health, signals, tasks, calendar, contacts, calibre, readwise, compte, social, layouts, thoughts, mail, pipelines.
- **Web** (`web/`, Astro): renders each member's garden as a themeable site under `/g/<member>`, and the public site (candide.me) on Cloudflare Pages.
- Plus a **browser clipper** (`clients/web-clipper`) that saves the rendered DOM of a page as an article fiche, like Carnet's share sheet.

**A message's path.** App POSTs to `POST /api/conversations/:id/messages` → server stores it (fans to a room's participants over WebSocket; in a multi-human room Maurice replies only when summoned with `@maurice`/`@claude`) → system prompt assembled (household context, member profile, armed persona, composer context; the content-safety floor always last) → history bounded to the model's context window → model resolved → MCP tools listed and filtered by tool families → streamed request with prompt-cache breakpoints → newline-delimited `StreamEvent`s back (`text_delta`, `thinking`, `ping`, `tool_call`, `tool_data`, `usage`, `done`, `error`) → tools executed and fed back, up to 6 rounds → app renders prose live and draws tool results as data cards from the data itself.

**Delivery: a container, and only a container** (decided 14 September 2026; the notarized `.pkg` is retired). `infra/container/Dockerfile` has two targets: `dev` (bind-mounted sources, Calibre, the private overlays) and `production` (sources copied in, 2 MCP tools — garden, corpus — no Calibre, ~2 GB, behind Caddy with Let's Encrypt; the build fails on a dangling symlink rather than ship a private repo). Base image Ubuntu 26.04 (arm64; its Calibre 9.2 opens a modern library). `scripts/deploy.sh <host> [tag]` builds on the Mac, pushes through a registry (`MAURICE_REGISTRY`) or pipes over ssh, and recreates the households; `infra/cloud-init/maurice.yaml` prepares a machine; `infra/container/MULTI-HOUSEHOLD.md` + `ops/household.sh` run several households on one machine as separate compose projects behind one Caddy, each on a loopback admin port from 3101 up. `scripts/container.sh` drives the local container; `container.sh seed` snapshots the live SQLite databases with `VACUUM INTO`; `container.sh import <archive>` starts one from a household archive. Repo-relative state (`data/`, `logs/`, `tools/corpus/data`) is symlinked into the data volume by the entrypoint.

**A household costs ~260 MB idle** (measured 14 September 2026), so an 8 GB machine carries about twenty. **The home Mac is the exception**: it still runs launchd agents (`scripts/service.sh`): `com.maurice.api` (port 3001), `com.maurice.mcp-gateway`, `com.maurice.web`, nightly `com.maurice.backup`, and one `com.maurice.household.<name>` per extra household; it reads `~/.maurice/config.toml` and `~/.maurice/.env`. The local container publishes :13001 beside it, on a copy of the data.

**The first rented host, `maurice-fleet`** (since 17 September 2026): a Scaleway BASIC2-A2C-8G in Paris (2 ARM vCPU, 8 GB, Ubuntu 26.04, 51.15.217.40) carrying Aline's household and the App Review one, DNS cut over the same day; `MAURICE_REGISTRY=rg.fr-par.scw.cloud/maurice scripts/deploy.sh maurice-fleet` is the whole update (`/opt/maurice/image.env` records what was shipped; an already-built tag is the rollback). Everything Scaleway sits in a project `maurice` with one IAM key limited to Generative APIs and the registry, kept in `~/.maurice/ops/scaleway-fleet.env`. Its households are backed up nightly to Object Storage (see *The server → Backups*). The demo fleet (throwaway instances anyone can point the apps at, TTL a couple of weeks, public-domain seed) is the planned sibling of this host — the answer to the cold-start problem and the condition of the App Store being a channel at all.

**Networking** is the operator's plumbing, not Maurice's: Tailscale (private mesh, at home) or a Cloudflare Tunnel (public hostname). Known trap: `brew services restart cloudflared` regenerates the plist without `tunnel run` and takes the tunnel down.

**Gaps**: git is assumed present on the host (the server shells out to system `git`); the vector store lives in the repo tree (`tools/corpus/data`) rather than the data dir; no automatic provider failover. Hosted volumes unbacked was a gap until 19 September 2026 and is closed (restic, nightly).

## The server

`server/index.ts` mounts both halves. Listens on `PORT`, serves generated images and avatars, proxies `/mcp/*` to the gateway and `/g/<member>/` to the garden engine (both hardcoded to `127.0.0.1`), upgrades WebSockets for rooms.

**Chat-engine routes** (`server/src/routes`): `/api/auth` (setup, login, enroll, invite/pairing codes) · `/api/users` (roster, profiles, avatars, preferences, API tokens, guest contacts) · `/api/conversations` (threads and rooms, messages, streaming replies, participants, read state, per-conversation tool-family overrides, `/search` full-text over the member's rooms) · `/api/maurices` (personas; headed by Maurice Maurice) · `/api/files` · `/api/v1/gardens` (per-note sharing, web theme per audience) · `/api/v1/composer` (omnibox search, context assembly) · `/api/models` (roster per member, everyday-model preference) · `/api/tool-families` · `/api/reports` (operator moderation) · `/api/ancillary` (loopback-only: the Python tools ask the server for a model turn) · `/api/me/usage` (what the member spent today and this month against the tightest cap that applies to them) · `/api/admin/usage` (the admin's view of everyone) · `/api/admin/export` (the household archive, `application/gzip`, streamed, admin token; `GET /admin/export` is the same behind the console cookie) · `/api/admin/status` (carries the docs-refresh state) · `/admin`, `/login` (the household admin web UI: members, models and their context windows, provider keys, Calibre library, access grid, spending caps, ancillary pins, the docs refresh card, the household export). **Data-api routes** under `/api/v1/*`: `health/*`, `signals`, `coaching`, `tasks`, `tracks`, `dossiers`, `layouts`, `dashboard`, `places`, `uploads`, `compte`, `bank-transactions`; `garden-tools/*` (the owner's toolbar); `calibre/*`, `books`; `garden/articles`, `garden/entries`, `garden/links`, `garden/cards`; `articles/scrape` (legacy alias).

**The agentic loop** (`streamResponse` in `services/claude.ts`): system prompt → messages (the clock rides as a trailing system reminder, never in the system prompt, so the prefix stays cacheable; an assistant turn that called tools carries a compact *tool trail* — six results at most, 240 characters each — so the next turn reuses them) → model and provider → MCP tools sorted by name → **context-window fit** (`contextWindow.ts`: the model's `ctx` less the head, a reply reserve and a margin; over that the oldest turns are dropped to 70% of budget with hysteresis, the cut stored on the conversation as `context_from`, and the model told the beginning is missing) → stream; tool-use blocks run (web search via Tavily, or an MCP `callTool`), results minified and fed back; Stop reaches the provider on every path; an OpenAI-style round silent for 180 s is abandoned; `ping` every 15 s of silence; **`MAX_TOOL_ROUNDS = 6`**. Every model request logs a `[round]` line, every tool call a `[tool]` line.

**Prompt caching.** Anthropic: three explicit breakpoints (last system block, end of history, the tool-result trail), a cached read costing a tenth. Z.ai and Scaleway cache implicitly. Mistral and OpenAI cache only with a `prompt_cache_key`, which the loop sends (the conversation id; `PROMPT_CACHE_KEY_PROVIDERS`). Scaleway: only DeepSeek V4 Flash reports cached tokens (`prompt_tokens_details.cached_tokens`, priced at 0.2), and only on a hot shared prefix; the nine others return no cache detail — Cockpit is the only place to see it.

**Providers** (chosen per resolved model's `models.provider`, no failover): **Anthropic** (native loop, key `households.api_key`); **Ollama** (local, `ollama.ts`, a 32k window requested); **OpenAI / Mistral / Z.ai / Scaleway** through one Chat-Completions door, `openaiChat.ts` (`api.openai.com/v1`, `api.mistral.ai/v1`, `api.z.ai/api/paas/v4`, `api.scaleway.ai/v1` — or `api.scaleway.ai/<project>/v1` when the key is project-scoped, hence `scaleway_project_id` beside `scaleway_api_key`; `isOpenAIStyle()`, `openaiStyleBaseUrl()`, `openaiStyleKey()` in `claude.ts`). Reasoning models stream thinking under `reasoning_content` or `reasoning`; the loop reads either and raises `thinking` events without forwarding the text. A billing refusal is answered in plain language; Z.ai's code 1113 (empty account *or* model outside the package) is kept apart from a definite out-of-credits. **Echo mode** when no key at all. **A key is what makes a model exist**: `configuredProviders()` gates the apps' roster, the admin grid (callable models only; hidden rows carried over on save) and the ancillary pins alike. Seeded rosters: Anthropic (Claude Opus 4.8, Sonnet 4.6, Haiku 4.5), OpenAI (GPT-4o, GPT-4o mini), Mistral (Large, Small), Z.ai (GLM-5.3 text-only, GLM-5.3 Flash with `vision`, 1M windows), Scaleway (ten Serverless models: Mistral Small 3.2 — the Scaleway everyday default, reads images — Gemma 4 26B, Qwen 3.6 35B, GPT-OSS 120B, DeepSeek V4 Flash, Qwen 3.5 397B, Qwen 3 235B, Llama 3.3 70B, Mistral Medium 3.5, GLM 5.2; output capped at 16k or 32k per model; a 429 "INSUFFICIENT QUOTA" is a per-minute rate limit, not a billing error). `pricing.ts` prices every seeded model (Scaleway in euros converted at a fixed ECB rate, `EUR_USD`); an unpriced model prices at `null`, never zero.

**The reasoning switch** (since 18 September 2026): the roster says whether a model reasons and whether that can be switched (`models.thinking` ∈ `none` / `optional` / `always`); a persona records its choice (`maurices.thinking`, null / on / off) and the household one for the everyday Maurice (`households.everyday_thinking`, seeded to "answer directly", editable in the admin console only); each provider path translates it into the one field it reads — Z.ai `thinking: {type: enabled|disabled}`, Anthropic 4.6+ `thinking: {type: adaptive|disabled}` (sampling parameters yield to it on 4.7+; thinking blocks replayed with their signature in tool rounds), Ollama `think: true|false`. Scaleway's reasoning models are `always` and ignore it. Nothing is sent when the persona made no choice or the model has no switch.

**Ancillary models** (`services/ancillary.ts`, since 13 September 2026): everything that calls a model and is not the chat — summaries, flashcards, signal parsing, the tools' classifiers — is an *invocation* (twenty-two) resolved pin (`ancillary_models`) → household `ancillary_model` → chat default, skipping models whose provider has no key. Each tier (light/standard/heavy) has a European preferred list: Scaleway first (Mistral Small 3.2, GPT-OSS 120B, Qwen 3.5 397B), then Mistral; Anthropic and OpenAI are out by decision, Z.ai by size. Pins record `source` (`auto` follows the advice and is realigned at start, `admin` never moves; a deleted pin is never re-created). A household is offered only the tool invocations whose directory is present on the machine. The Python tools call `POST /api/ancillary` (loopback only, `middleware/loopback.ts`) through `tools/shared/model_config.complete()`; the ten research-pipeline invocations are `ownDispatch`. The admin card sits under *Advanced*, collapsed.

**The spending fuse** (`budget.ts`): a no-op unless a cap is set; it *refuses* where `pricing.ts` *measures*. **Three layers, the tightest wins**: the instance's env caps (`MAURICE_SPEND_CAP_USD` lifetime, `MAURICE_SPEND_CAP_DAILY_USD` rolling 24 h, summed over the household; the fleet host's `defaults.env` sets 10 USD daily) ≥ the household's own daily cap (`households.spend_cap_daily_usd`, "Daily spending cap" on the console's settings card) ≥ the member's (`users.spend_cap_daily_usd`, on the member's edit page, summed over that member's turns). Checked at the top of every agentic round with the turn's running cost passed in; refuses an unpriced model under any cap; Ollama exempt by provider; the refusal names the closest cap ("You have reached your daily limit…", "This household…", "This instance…") and emits usage then an `error` event. Spend is written to `spend_ledger` by `addMessage` with `user_id` (in a room, the sender of the message Maurice answered). `GET /api/me/usage` returns `today_usd` (24 rolling hours), `month_usd` (calendar month), `cap_daily_usd` (the tightest that applies, or null), `remaining_usd`; `GET /api/admin/usage` returns everyone's; the console shows each member's spend today in the members list, today and this month on their page.

**Rooms**: `conversation_participants`; Maurice answers only when mentioned (`mentionsMaurice()`); the ➤ button posts `{ summon: true, maurice_id }`, 💬 a human-only message. Liveness through `roomBus.ts` (a per-room channel and a per-user channel at `/api/me/ws`). Reports and blocks in shared rooms only.

**Auth**: admin created at `POST /api/auth/setup`, logs in with username + password; standard members log in with `user_id` + a mandatory PIN (identical "Invalid credentials" whatever the cause, rate-limited per IP); guests enroll without one; `POST /api/auth/enroll` redeems an invite code (rate-limited per IP and globally); pairing tokens are the one-shot programmatic path. Opaque session tokens; `maur_*` API tokens scoped `mcp` / `health` / `full` (`health` opens only `/healthz`'s full face; `mcp` is not enforced and behaves as `full`). Roles `admin` / `standard` / `guest`. **The admin dashboard is loopback-only** on three signals: loopback socket peer (Bun's `requestIP`), loopback `Host`, no Cloudflare edge header (`cf-ray` / `cf-connecting-ip`) — so a hosted household's `/admin` is a permanent 403 and is reached through an ssh forward (`ops/admin.ts <name>`). Image references in message bodies are confined to the images directory (`resolveImagePath`, `server/test/image-path.test.ts`).

**Health & ops**: `GET /healthz` public (`status`, `service`, `version`) or, with a token, `git_sha`, `built_at`, `schema_version`, `uptime_s`, `db` (a `quick_check` cached five minutes, `DB_CHECK_TTL_MS`), `disk_free_mb`, `errors_1h` / `errors_24h` / `last_error_at` / `last_error_kind`; 503 when degraded. Version from `git describe` first, then `server/build-info.json` (stamped by `scripts/build-info.sh` at image build); `MAURICE_VERSION` / `MAURICE_GIT_SHA` / `MAURICE_BUILT_AT` override; `resolveBuildInfo` lives in `services/buildInfo.ts`. The operator tooling lives in `ops/`: `fleet.yaml` (inventory: `deploy:`, `restart:`, `admin:` per instance), `fleet-status.ts` (one table, exit 1 when anything is down), `tower.ts` (TUI: `d` deploys, `R` restarts, `a` opens an admin console), `admin.ts`, `recreate-container.sh`, `mint-health-token.ts`, `backup.sh`, tokens in `~/.maurice/ops/fleet-tokens`; Uptime Kuma and Dozzle are the named off-the-shelf stack, an error collector not wired. No discovery, no central registry, no fleet UI — decided against.

**Documentation refresh** (`services/mauriceDocsRefresh.ts`, since 19 September 2026): `MAURICE_DOCS_URL` names where Maurice Maurice's notes are published (default the repo's `docs/maurice/` on `main` via raw.githubusercontent.com; `off` makes no outbound call, the default under `NODE_ENV=test`; passed through from the household's `.env` by the compose files). 20 s after boot, then every 24 h, the server GETs `manifest.json` (15 s timeout, 64 KB cap, the article-extraction SSRF guard; `MAURICE_DOCS_ALLOW_LOCAL=1` lifts it for a private mirror); if its `generated_at` is newer than the manifest on hand, it downloads each note whose sha256 differs (2 MB cap, hash verified), stages the set and swaps it into `~/.maurice/docs/maurice`; any failure leaves the previous set. Log lines `[docs] refreshed to …` / `[docs] up to date (…)` / `[docs] refresh failed: …`. `docsDir()` chooses `MAURICE_DOCS_DIR` if set, else the refreshed set when at least as new as the bundle, else the bundle. `GET /api/admin/status` carries `docs: { source, generated_at, last_check_at, last_error }`; the admin dashboard's last card shows date and source with "Check now" (`POST /admin/docs/refresh`).

**Backups.** *Hosted households* (since 19 September 2026): `infra/host/backup.sh` runs from the host's crontab at 03:30 UTC — the running container writes a consistent copy of every SQLite database (`VACUUM INTO`), then restic, in its own container with the volume read-only, sends the volume minus the live databases to one repository per host on Scaleway Object Storage (bucket `maurice-fleet-backups`, project `maurice`), 14 daily / 8 weekly / 12 monthly kept, encrypted with a password only the Mac holds (`~/.maurice/ops/fleet-backup.env`). `ops/backup.sh restore-test <host> <name>` restores the latest snapshot into a throwaway household, boots it and tears it down (rehearsed on both households); `ops/backup.sh restore` does it for real. *The Mac*: `com.maurice.backup` snapshots `maurice.db` and `life.db` nightly into `~/.maurice/backups/db` (`scripts/backup-db.sh`); gardens rely on git; `compte.db`, `recommendations.db` and the git-ignored flashcards are not covered.

**Gaps**: above the fuse nothing yet — no balance, no prepaid quota, no statement a customer can read; Scaleway's cache invisible on nine models out of ten; tool trail is plain text in history (a small model could imitate it); no failover; a moved household keeps stale local models; context estimated by characters, and the cut never moves back for a bigger model; the Mac's backup is partial; `mcp` scope unenforced; an error collector undecided; the tracks data-api routes carry no member check (SSRF guard on `/reports/img`, bare-basename checks on `uploads` and `bank-transactions`, `noPathTraversal` on tracks/reports were added in September 2026).

## The data model

One SQLite file, `maurice.db` (WAL), in `~/.maurice/`; the whole schema is `server/src/db.ts` — `CREATE TABLE IF NOT EXISTS` plus append-only guarded `ALTER`s and idempotent backfills, no migration framework, `PRAGMA user_version` stamped by `SCHEMA_VERSION`. The data-api keeps its own files under `~/.maurice/data/` (`MAURICE_DATA_DIR`): `life.db` (highlights, reading positions, health, tasks, signals, dossiers, coaching, layouts, places; renamed from `akita.db` on 13 September 2026), `compte.db`, `recommendations.db`; plus the corpus vectors and the Calibre library.

- **Identity**: `households` (one row `id='default'`: the provider keys `api_key`, `openai_api_key`, `mistral_api_key`, `zai_api_key`, `scaleway_api_key` + `scaleway_project_id`, `fal_api_key`; `default_model`, `ancillary_model`, `max_tokens`, `everyday_thinking` (nullable 0/1, seeded 0), `spend_cap_daily_usd`, `ollama_host`, `default_tool_families`, `color`, `icon`, the `*_seeded` guards incl. `vision_seeded`, `thinking_seeded`); `users` (`username` is also the garden directory; `role`, `pin_hash`, `profile_text`, `experimental_tools`, `everyday_model`, `spend_cap_daily_usd`); `user_preferences` (theme, font, density, palette, locale).
- **Auth & devices**: `sessions`, `api_tokens` (`token_hash`, `scope`), `invite_codes`, `device_tokens` (APNs, with `household_tag`), `devices` (pairing, unused by the app), `guest_contacts`.
- **Conversations**: `conversations` (`maurice_id` null = everyday, `origin` `'anthropic'` for imports, `tool_families`, `context_from`); `messages` (`author_id`, `maurice_id`, `model`, `data` = frozen tool results for the data cards, `usage`); `messages_fts` (FTS5, trigger-maintained); `conversation_summaries` (keyed on a transcript hash); `conversation_participants` (`last_read_at`); `reports`; `spend_ledger` (`at`, `provider`, `model`, `cost_usd`, `user_id` indexed with `at`; rows from before the column stay null and count only in household sums; a deleted message never un-spends).
- **Files**: `folders`, `files` (bytes at `{dataDir}/files/{id}{ext}`).
- **Gardens**: no `gardens` table — `note_shares` (owner, slug, member) and `garden_settings` (audience key → `web_theme`); the content is Markdown under `~/.maurice/gardens/<username>/`, one git repo per member.
- **Personas & composer**: `maurices` (incl. `thinking` nullable 0/1), `maurice_access`, `composer_specs` (keyed conversation + account); both `context_json` and `spec_json` are frozen resolved sets.
- **Models**: `models` (`tier`, `vendor`, `provider`, `ctx` in k tokens, `vision`, `thinking` ∈ `none`/`optional`/`always` — Ollama fills it from `/api/show`; prices are in `pricing.ts`, not here), `user_model_access` (standard members' allow-list; admins computed-all), `ancillary_models` (`invocation`, `model_id`, `source`).
- **Bridge**: `calibre_libraries` (one global library, set in the admin).

Tool families resolve **conversation → persona → household default → tier default**. **Gaps**: single household per server; room context shared not per-participant; the ledger counts money not tokens (an unpriced model records nothing); hand-rolled migrations — the guest-role rebuild of `users` had dropped `everyday_model` and `experimental_tools` on old databases, fixed 19 September 2026 with a test booting the schema over a pre-guest database; test isolation by environment (lazy imports).

## The MCP tool ecosystem

`tools/mcp_gateway/server.py` discovers every tool server under `tools/` at startup (three shapes: `gateway_context`, a module-level `app`, or a FastMCP `mcp`), namespaces tools as `{server}__{tool}` (`garden__create_note`, `signals__signal_log`), serves a unified endpoint and per-server ones over Streamable HTTP. Per-member context comes from the `X-Maurice-Member-Id` header into a contextvar (`tools/shared/context.py`: `get_member_id()` / `require_member_id()`). Auth: a bearer token (`MAURICE_MCP_TOKEN`) for the loopback caller, and OAuth 2.1 / PKCE (`oauth.py`) accepting `maur_*` tokens — which is what lets Maurice be a custom connector in an external Claude client. `tools/shared/config_loader.py` reads `~/.maurice/config.toml`; `model_config.py` resolves ancillary models.

The engine's client is `server/src/services/mcpClient.ts`, through the `/mcp/*` proxy. **Tool families** gate the roster: the tier default is empty for every model; only `web` and `signals` are always on; `garden` is sub-split into `garden-notes`, `garden-journal`, `garden-people`, `garden-fragments`, `garden-media`, `garden-publish`, `garden-other` (`services/toolFamilies.ts`). Everything but `web`, `signals`, `garden-notes`, `garden-journal` is **experimental** and hidden until an admin ticks *experimental tools* on the member. The system prompt names only the families actually present (`toolRosterNotice()`), web search only when Tavily is configured, image generation only when a fal key exists.

**Public vs. private** is enforced by `.gitignore` and the container's dockerignore: public `garden`, `corpus`, `shared`, `mcp_gateway`; everything else is the `maurice-tools` overlay. Secrets in `.env`, never in tracked config.

**`mail`** (private overlay, September 2026): reads Proton (via Bridge) and iCloud mailboxes; the only write is `triage(account, uid, action)` over a closed vocabulary in the config (states `01 · Répondre`… `Archive`, topic labels); no send, no delete, no arbitrary move; bodies returned stripped and wrapped as untrusted; deterministic `[rules]` run before the model (46% of the inbox); a nightly launchd proposal (`com.mail-proposal`) classified by local `qwen3.6:35b-a3b` with reasoning off; an audit log at `~/.maurice/mail-audit.jsonl`; reading horizons per state (120 days, 180 for `to_reply`). Its config is one person's method and gates sharing the code.

**Gaps**: the gateway itself enforces neither families nor the experimental flag (a direct MCP client gets the full roster); `web` and `signals` cannot be turned off; the parent `garden` prefix opens all sub-families; no per-tool sandboxing; discovery is positional; résonances and flashcards have no MCP face; Homebrew's `python@3.14` needs `scripts/fix-python-expat.sh` after every upgrade.

## The web garden

`web/` is the Astro engine. **Themes** live under `web/themes/<name>/` (`theme.json`, `global.css`, `layouts/Base.astro`, `views/*.astro`), resolved per request in `web/src/middleware.ts`: `?theme=` (wins, sets a year-long dated cookie `<name>.<unix seconds>`) → that cookie, *while it is newer than the owner's choice* → `X-Maurice-Theme` (the app's picker, stored in `garden_settings.web_theme`, its date sent as `X-Maurice-Theme-Since`) → `THEME` env → `manuscript`. The app itself opens a garden through `/login?…&theme=X`, so the cookie is usually the owner's earlier pick; an undated cookie yields. Shipped garden themes: manuscript, botanical, newsprint, terminal (`default` is the hidden base). Collections: notes, blog, essays, pages, resources (books, articles, movies, series, podcasts, games, people — the cards), fiches (`<slug>-fiche.md`, private garden only). Routing is locale-aware (`/` English, `/fr/` French). `public` flag = published; `encrypted` notes are encrypted in the built HTML (AES-256-GCM, `PRIVATE_CONTENT_PASSWORD`). Wiki-links `[[slug]]` and typed refs `[text](note:slug)` become links (`remark-cross-ref.mjs`); MOC notes render their children as cards.

**One built engine per household** (since 14 September 2026): `web/dist/server/entry.mjs`, started by `scripts/start-web.sh` on :4321, loopback only; the Bun proxy sends `X-Maurice-Garden`, `X-Maurice-Base`, `X-Maurice-Theme`, `X-Maurice-Theme-Since`, `X-Maurice-Owner`, `X-Maurice-Shared` (all stripped from incoming requests first) and the engine reads them into an `AsyncLocalStorage` (`src/lib/garden-context.ts`). Every collection is read off disk per request (`web/src/lib/content-fs.ts`, `notes-fs.ts`) with mtime caches; ~127 MB for a four-member household against ~1.44 GB of dev servers before. Live reload streams from `GET /api/v1/garden-tools/events` (one `fs.watch` per garden). Images are served by the server off disk at `/images/<member>/**` (own garden entirely, another member's only under `resources/`); `/api/images/<name>` is what Maurice writes into a note body, unauthenticated. The remote-cover sweep is the server's (`services/gardenImages.ts`, after boot).

**The owner's toolbar** (flip public/private, delete, drag-reorder a MOC, open in Obsidian or Working Copy, translate, share to social) calls `POST /api/v1/garden-tools/*`, always on the caller's own garden; writes go through `atomicWrite` + `autoCommit`. `translate` and `social-publish` need the source checkout and answer 501 in the container. **Owner mode** is `Astro.locals.owner` from the proxy header (`GARDEN_OWNER=1` for a bare `astro dev`). The public site publishes to Cloudflare Pages via `scripts/publish-web.sh`; a Pages function adds `?t=YYYY-MM-DD` time travel from an R2 bucket. **Tests**: `web/e2e/` (Playwright, `npm run e2e`), a seeded throwaway household, 73 tests green against both the dev server and the build; `docs/garden-server-mode.md` records the chantier.

**Gaps**: the private overlay `maurice-web/` is symlinked into `web/src` (use `grep -R`); the activity indicator is transient; the search index is single-locale. Per-garden theme wiring is joined (dated 19 September 2026): a reader's `?theme=` cookie holds only until the owner picks again.

## Specialized Maurices & hats

A **persona** is a row in `maurices` (`services/maurices.ts`, routes `routes/maurices.ts`): `name`, `tagline`, `hat`, `palette`, `prompt`, `model` (null → the member's everyday model), `temp` (0–1), `thinking` (null = provider default, true = think first, false = answer directly; offered only on a model the roster marks `optional`, kept when the model changes), `context_json` (a frozen composer spec — the baked-in context, shown locked in the tray), `tool_families`, `created_by`. Personas are private to their creator; a guest gets the ones an admin grants (`maurice_access`). The **everyday Maurice** is a null persona: no hat, no bound context, the member's `everyday_model`, the household's `everyday_thinking`. Sixteen hats (`app/Maurice/Views/Hats.swift`: boater, fedora, top hat, beret, flat cap, ball cap, chef, grad, hard hat, detective, explorer, wizard, crown, party, swim, captain), each with a palette; the hat shows in the chat header, the sidebar rows and the send button. In the app: **Maurice Studio** (`StudioViews.swift`) picks and arms a Maurice; the **Persona Creator** (`PersonaCreatorView.swift`) edits name, tagline, prompt, hat, palette, creativity, a reasoning switch (three pills, shown only when the model's phase is optional), bound context; the empty conversation shows a greeting card, with a reasoning pill when the persona chose.

**Maurice Maurice** (since 18 September 2026) is the built-in specialist of Maurice: not a row (`builtinMaurice()`, id `maurice-maurice`), first on every member's list including guests, uneditable and undeletable (403), boater hat, creativity 0.3, `thinking` false, tagline in the member's language, prompt telling him to answer from the documentation in the asker's language, name the note he draws on, respect "ships vs. exists" and "gaps", and say when the docs are silent. His context is this documentation, read by `services/mauriceDocs.ts` (cached on mtimes) from `MAURICE_DOCS_DIR` if set, else the refreshed set under `~/.maurice/docs/maurice` when at least as new as the bundle, else the repo's `docs/maurice/` (a snapshot `scripts/sync-docs.sh` copies out of the owner's garden with a `manifest.json` — date, size, sha256 per note — shipped in the image and refreshed daily by `mauriceDocsRefresh.ts`): the digest (~12k tokens) plus, in full, any note under the index dated after its `covers` entry; a note marked `internal: true` is skipped by reader and sync script alike. His model is the server's pick (`builtinMauriceModel()`), locked, outside the member's allow-list: Claude Sonnet 4.6 on an Anthropic key, Mistral Medium 3.5 on Scaleway, then Mistral Large, GPT-4o, GLM-5.3, the household default's provider first, never a local model; with no cloud key he falls back to the household default. The chat's model pill shows a lock. Tool families inherited from the household default.

**Gaps**: hats are chosen, not emergent; persona creation is manual; the everyday Maurice's settings are the household's, not the member's; Maurice Maurice's notes reach other households only through a push of the repo (the refresh closes the gap between a push and an image rebuild, not between the garden and a push), and they are English only; fine detail lives in the delta or nowhere — the next step, if it bites, is a read-on-demand tool for one full note.

## The context composer

The app's context tray (`Views/ComposerViews.swift`) over `server/src/services/composer/*` and `routes/composer.ts`. Loadable: **notes** (with descendants following `[[wiki-links]]` breadth-first, include-archived, exclusions), **books** (chapter scope `all` / `up_to` / pick / `progress`; representation `summary` or `full`), **fiches** (with fragments), **past conversations** (summary past 8k tokens, cached against a transcript hash in `conversation_summaries`, generated asynchronously; `representation: full` pins the transcript; `GET /api/v1/composer/conversations/:id/summary?wait=1`), **files**, **folders**. The **omnibox** `GET /api/v1/composer/search` searches all of them, ordered by `updated_at` by default (Relevance and Title in the sort menu). The tray shows a running total against a **200,000-token budget** (`CTX_BUDGET` in `composer/weights.ts`), colour-graded; binaries carry no estimate and ride as content blocks. Two layers: **baked-in** (a persona's `context_json`, locked) and **added** (removable). **Frozen snapshots** (`composer/specs.ts`): the resolved set is frozen at save, the content stays live; refresh to regrow. A book on **`progress`** follows `reading_progress` (Carnet's reader writes it), loads summaries up to the reader's chapter, recomputes each turn, can be **paused** (consulting ahead does not count as read) or **reset**; the block names the book, its authors and calibre `book_id`, chapters numbered the reader's way (1-based over body chapters, front/back matter unnumbered — `classifyChapters` and the tool's `_body_chapters` agree); the system prompt carries *Books in this conversation* and *Reading in progress* sections; "I've read three more chapters" calls `calibre__set_reading_progress`.

**Ships**: notes, conversations, files, fiches. **Books** need the experimental Calibre tool. **Gaps**: room context is shared; the budget is a fixed 200k, not the model's window, and loaded context is never trimmed to fit.

## Shared gardens

Sharing is a fact about a **note**; gardens are **derived** (`services/gardens.ts`, `routes/gardens.ts`). A note's audience = owner + `note_shares` rows; `audienceKey()` sorts and joins member ids; a garden is the set of notes with the same key, computed on the fly (`gardensFor(memberId)`); `garden_settings.web_theme` per audience. Verbs: `GET /api/v1/gardens`; `GET /api/v1/gardens/note/:owner/:slug/access`; `POST …/share`; `POST …/leave` (remove yourself); `PATCH /api/v1/gardens/:id` (theme). ## The files library

Per-member folders and files (`FilesLibraryView` in `SettingsView.swift`; `services/files.ts`, `routes/files.ts`). Nestable folders by `parent_id`; create, upload (iOS file importer or camera; macOS drag-and-drop), rename, delete (cascades, unlinks bytes); **5 GB quota** per member. Kinds by extension: text (`.md`, `.txt`, `.csv`, `.json`, `.yaml`, `.log`, `.rtf`), image, PDF, generic. Bytes at `{dataDir}/files/{id}{ext}`, served raw at `/api/files/{id}/raw`. Attaching goes through the composer: text becomes prompt text, binaries become content blocks (no token estimate, de-duplicated by id). **Gaps**: browsing lives in Settings; no iOS drag-and-drop; no previews or full-text search of file contents.

## Households, rooms & devices

**A server is one household; a device can hold several; switching member is a tap and a PIN.** First run (`PairingView.swift`): enter a server URL, `GET /api/health` confirms it and returns the household's name, colour and icon; `SessionStore.swift` persists paired households with one session token each (`maurice.token.<household>.<user>`); `switchHousehold()` flips the active one; `refreshFoyers()` polls each for unread badges. `UserPickerView.swift`: PIN login (`POST /api/auth/login` with `user_id` + `pin`), admin login (username + password), or an invite code (`POST /api/auth/enroll`, then `/api/auth/set-pin`; guests need no PIN). Invite codes: 8 characters from an unambiguous alphabet, one active per member, ~7 days, reusable in the window. **Roles**: admin, standard, guest — a guest's reach is `guest_contacts`, checked both directions (`guestCanReach()`), plus the personas granted. **Rooms**: a 1:1 is a room with one human; `addParticipant()` enforces guest reach; in a room 💬 (human-only) is the default button and Return posts it, ➤ summons Maurice with ⌘Return; read state per participant. **Moderation**: long-press → Report or Block in shared rooms only; reports at `/api/reports`, child-safety first. **Push**: APNs (`push.ts`, `apns.ts`, ES256 over HTTP/2), tokens with `platform` and `household_tag`, dead tokens pruned.

**The household archive** (since 19 September 2026): a versioned `.maurice.tar.gz` (`maurice-archive` v1, `services/archive.ts`, format in `docs/household-archive.md`) holding everything the household *is* — `maurice.db` and the data-api databases as `VACUUM INTO` snapshots, the gardens with each member's git history and `gardens.json`, images, files, uploads, avatars, `config.toml`, and a `manifest.json` (household, members, schema and server version, contents). Left out: backups, logs, the corpus vector index (regenerable), `.env`, the Mac's `ops/` secrets, the bare remotes under `~/.maurice/git`. It contains the provider keys: **it is a secret**. Export: the console's section 07 "Export this household" (`GET /admin/export`) or a bearer token on `GET /api/admin/export`, streamed. Import into an empty data directory (refused if a `maurice.db` is there): `scripts/import-household.sh <archive> [dir]` on a Mac, `scripts/container.sh import <archive>` for a local container, `ops/household.sh add <host> <name> <domain> --from <archive>` on a shared host (over ssh's stdin, no copy stays). Still by hand after: the corpus index and the gardens' `origin` remotes. This is the hand-over of a hosted instance: the owner exports from their own console, the new place imports, the operator never opens the data.

**Gaps**: single-tenant server; the `/api/auth/pair` device ceremony is implemented but unused; sessions don't expire; guest persona access has no override.

## Knowledge capabilities

**Garden** (`tools/garden/server.py`, ships): full CRUD over the Markdown garden, always on request. **Highlights & résonances** (ship with Carnet): highlights in SQLite per member, anchored to chapter or fiche and to the view (full/summary); a résonance is a dated block under `## Résonances` on the target's fiche with a literal `[[wiki-link]]` — no link table, the markdown is the truth.

**Flashcards** (ship, September 2026): generated on demand from a chapter, a book, a fiche or a fragment, highlights covered first; one file per pass in the **Obsidian Spaced Repetition** syntax (`Question::Answer`, `?`, `:::`/`??`, `==cloze==`, a `#flashcards/<collection>/<slug>/<unit>` deck line) with the plugin's `<!--SR:…-->` schedule; frontmatter holds the source hash (stale detection) and a fingerprint per card (hand-edited cards survive regeneration); `_cards/` is git-ignored; language French by default, `cards_lang` on the fiche, `lang`/`answer_lang` per call, a *vocabulary* mode; `/api/v1/garden/cards`.

**Tracks** (`tools/tracks`, experimental): `request_deep_research`, `get_research_status`, `generate_briefing`, `get_latest_briefing`, `get_dossier`, `get_dossier_tree`, `list_dossiers`, `trigger_signal_report`; SQLite storage; findings can be published to the garden.

## Applications, plugins, and the case of the mail
